# Item Gate — Design

- **Date:** 2026-09-23
- **Mod:** Easy Storage (`easystorage`), Fabric, Minecraft 26.2, Java 25
- **Status:** Approved in brainstorming, pending spec review
- **Related:** [Sorter Hopper](2026-09-23-sorter-hopper-design.md)

## Goal

A single block that turns a pile of items, including full shulker boxes, into a
steady stream of dropped item stacks for a water-stream sorting system. It
behaves like a dropper that needs no redstone clock: while it holds items, it
drops one stack every 8 ticks out of its output face. Shulker boxes are unloaded
stack by stack, then the empty shulker box itself is dropped. Sorter Hoppers
along the water stream pick the stacks up.

## Behavior

### Placement and orientation
- `FACING`: all 6 directions. Set like a vanilla dropper: the output face points
  toward the placing player (`context.getNearestLookingDirection().getOpposite()`).
- `ENABLED`: a redstone signal locks it (same semantics as the Sorter Hopper and
  vanilla hopper). Unlocked by default.
- `OPEN`: true while at least one player has the screen open (barrel-style
  opener counting). Only changes the front texture.

### Inventory
- 27 slots.
- Screen: the vanilla generic 9×3 chest screen (`ChestMenu.threeRows`). No custom
  menu or screen. Title "Item Gate" or the anvil custom name.
- Automation (hoppers, droppers, Fabric Transfer API) can insert from any side.
  A hopper placed on the output side may also pull items out (standard container
  behaviour, not prevented).

### Drop cycle
Runs every 8 game ticks (`HopperBlockEntity.MOVE_ITEM_SPEED`) while the gate is
not redstone-locked and not empty.

1. If the block at `pos.relative(FACING)` has a full collision shape
   (`isCollisionShapeFullBlock`), wait: drop nothing this cycle.
2. Take the first non-empty slot, in slot order.
3. If that stack is a shulker box whose `CONTAINER` component still holds items:
   remove the first non-empty stored stack from the component, write the
   component back, and drop the removed stack. The shulker box stays in its slot.
4. Otherwise (any other item, or a shulker box with no stored items): remove the
   whole slot stack and drop it.
5. Mark the block entity changed so comparators update.

A cycle drops exactly one stack (or nothing when blocked, locked or empty).

### Dropping
- The dropped stack spawns as one `ItemEntity` whose centre is 0.3 blocks outside
  the centre of the output face, with zero velocity.
- No sound, no particles.
- Only shulker boxes are unloaded. Other item holders (e.g. bundles) drop as
  they are.
- An emptied shulker box keeps all its components (custom name, colour via item
  type, etc.) apart from the stored contents.

### Comparator
- Standard container signal over all 27 slots.

### Breaking
- Drops all 27 slots' contents, including a partly unloaded shulker box with
  its remaining items.
- The block drops as an empty item; custom name preserved (same loot pattern as
  the Sorter Hopper).

### Recipe
- Shapeless: 1 barrel + 1 dropper + 1 hopper + 1 repeater → 1 Item Gate.
- Category `redstone`. Recipe book entry unlocked when the player obtains a
  dropper.

## Architecture

All code under `tr.gokhan.easystorage`.

| Unit | Responsibility |
|---|---|
| `block/ItemGateBlock` | `FACING` (6-way), `ENABLED`, `OPEN`; placement; redstone lock; open menu; comparator; drops on removal; ticker hookup. |
| `block/entity/ItemGateBlockEntity` | 27-slot storage (vanilla `RandomizableContainerBlockEntity` pattern, like the barrel); opener counting that sets `OPEN`; drop-cycle tick; NBT via vanilla container helpers; menu via `ChestMenu.threeRows`. |
| `block/entity/ShulkerUnloader` | Pure helper, no world access. `takeNext(ItemStack shulker) -> ItemStack` removes and returns the first non-empty stored stack (or `ItemStack.EMPTY` when none); `hasContents(ItemStack) -> boolean`. |
| `registry/ModBlocks`, `registry/ModBlockEntities` | Registration additions (same patterns as the Sorter Hopper). |

Approach rationale: an independent block + block entity avoids mixins and access
wideners; subclassing vanilla `BarrelBlock`/`BarrelBlockEntity` or `DropperBlock`
is rejected (hard-coded vanilla types, redstone-pulse design). Reusing the vanilla
chest menu means no new menu type and no screen code.

## Art

Style: Vanilla+ (see Sorter Hopper spec). Barrel-style full cube, placeholders
generated by `tools/placeholder_textures.py` (extended), no Mojang PNGs copied.

| Texture | Look |
|---|---|
| `item_gate_side` | Barrel-style staves, dark teal tint (distinct from the Sorter Hopper's blue) |
| `item_gate_front` | Output face: dark hole with an orange rim (orange = output, mod-wide) |
| `item_gate_front_open` | Same, brighter interior; shown when `OPEN=true` |
| `item_gate_back` | Plain lid |

Model: parent `minecraft:block/cube_bottom_top` (`top` = front, `bottom` = back,
`side` = side), with blockstate x/y rotations per `FACING` mirroring the vanilla
barrel blockstate. Item model uses the closed block model with standard block
display transforms (inherited through `cube_bottom_top` → `block/block`).

## Testing

Fabric GameTests:

1. A stack in the gate drops from the output face as one whole `ItemEntity`
   stack.
2. A shulker box with 3 stored stacks drops them in 3 cycles; the 4th cycle
   drops the now-empty shulker box, with its custom name intact.
3. A full solid block on the output face: nothing drops.
4. Redstone signal: nothing drops; `ENABLED=false`.
5. Timing: consecutive drops are 8 ticks apart.
6. A hopper feeding the gate inserts items; comparator output reflects all 27
   slots.
7. Breaking drops contents, including a partly unloaded shulker box with its
   remaining stored items.
8. Integration: an Item Gate facing down onto a Sorter Hopper (filter: diamond)
   above a chest; the gate holds diamonds and dirt. Diamonds end in the chest;
   dirt does not.
9. `ShulkerUnloader`: empty shulker returns `EMPTY`; stored stacks with gaps are
   returned in slot order; `hasContents` turns false after the last stack.

Manual check in `runClient`: placement direction, textures (front/open/back/side),
chest screen, and a real water stream with 3 Sorter Hoppers and an end-of-stream
catch.

## Out of scope for v1

- Animated opening beyond the `OPEN` texture swap.
- Blocking extraction through the output face.
- Configurable speed; sounds/particles.
- Unloading item holders other than shulker boxes.
- Final textures.
